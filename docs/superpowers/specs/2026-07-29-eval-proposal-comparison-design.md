# Evaluation-Proposal Comparison Experiment (toy env)

Date: 2026-07-29
Status: approved by user (design dialogue in session)

## Goal

Evaluate ONE fixed `approx_penalized_hindsight` policy on evaluation sample
paths generated by three different sample-path-length proposals, to compare the
resulting discounted-cost estimators (bias / variance / compute cost).

The policy is identical across all three arms:

* agent: `approx_penalized_hindsight` (`ApproxQAgent`),
* internal SAA proposal: mixture geometric with `target_discount_factor=0.99`,
  `discount_factor_proposal=0.95`, `lambda_0=0.1` (the
  `mixture_probability_toy_study` lambda_0=0.1 variant),
* penalty coefficients: loaded from the already-trained
  `experiments/results/mixture_probability_toy_study` JSONL records
  (filtered by `mutate_val=0.1`, `sample_path_number=256`), never retrained,
* `sample_path_number=256`, linear penalty generating function.

Environment: toy env, initial-state congestion 0.5, discount factor 0.99 —
byte-identical `env_args` to `mixture_probability_toy_study`.

## The three evaluation arms

| experiment_name | evaluation proposal spec | period_weights | notes |
|---|---|---|---|
| `toy_eval_proposal_geometric_099` | `{'type': 'geometric', 'discount_factor_proposal': 0.99}` | all 1 | unbiased plain-MC baseline, long paths |
| `toy_eval_proposal_fixed_459` | `{'type': 'fixed', 'max_length': int(geom.ppf(0.99, 0.01)) - 1}` (= 458) | `0.99**(t-1)`, t = 1..459 | truncated-horizon estimate over 459 decision periods; ~1% tail weight dropped by design |
| `toy_eval_proposal_mixture_095_l01` | `{'type': 'mixture_geometric', 'target_discount_factor': 0.99, 'discount_factor_proposal': 0.95, 'lambda_0': 0.1}` | bounded in [1, 10] | unbiased IS, short paths |

Per arm: 4096 evaluation paths, `warm_up_periods=0`, fixed initial state (no
randomization). All arms start from the same arrival RNG seeds (env_args
identical, seeds offset +1001 inside `generate_test_paths_and_init_state`),
but the arms are NOT common-random-numbers paired: each proposal consumes the
shared RNG stream differently when drawing lengths (fixed draws none,
geometric one per path, mixture via QMC seeds), so the arrival streams
desynchronize and the three arms are effectively independent samples.
Variance comparisons across arms must treat them as independent, not paired.

The fixed horizon 459 is computed in code as `int(scipy.stats.geom.ppf(0.99,
1 - 0.99))` with an assertion that it equals 459 — not hard-coded. The
proposal itself uses `max_length = 459 - 1 = 458`: rolling a policy over a
sampled tail of N arrivals visits N + 1 decision periods (the trailing period
carries a stage cost but no arrival), and `_evaluation_period_weights`
therefore computes N + 1 weights. `FixedLengthProposal(459)` would raise
`ValueError` there (survival probability is 0 at period 460); the established
`-1` convention (see `mutate_fixed_length_for_sample_path_length_proposal`)
yields tails of 458 arrivals evaluated over exactly 459 weighted decision
periods. Verified empirically before planning.

## Why decoupling is needed (current state)

`generate_test_paths_and_init_state` ([param_generation/datasets.py:284-320])
currently draws the evaluation tails from the proposal spec found in the
agent's own `agent_args` (`sample_path_length_proposal` /
`sample_path_proposal`). The evaluation-path distribution is therefore coupled
to the policy's internal SAA proposal: changing the evaluation proposal changes
the policy itself (its agent_args, cache signature, and internal sampling),
which would make the three arms evaluate three different policies.

## Changes

All changes are backward compatible; omitting the new parameters preserves
current behavior exactly.

### 1. `param_generation/datasets.py` — `generate_test_paths_and_init_state`

Two new optional keyword parameters:

* `evaluation_proposal_spec=None` — when not `None`, the evaluation tails and
  `period_weights` are built from `build_proposal(evaluation_proposal_spec)`
  instead of the agent's spec. The `policy_specs` embedded in each record keep
  the untouched agent proposal. When `None`, fall back to the agent spec
  (status quo).
* `penalty_coefficients_dir=None` — passed through as `folder_path` to
  `load_trained_coefficients_from_folder`, so a new experiment_name can reuse
  coefficients trained under a different experiment's results folder without
  copying files or retraining.

### 2. `param_generation/registry.py` — three new `ExperimentSpec` entries

`toy_eval_proposal_geometric_099`, `toy_eval_proposal_fixed_459`,
`toy_eval_proposal_mixture_095_l01`: all with `config_type='toy'`,
`val_args=[0.1]`, `mutate=mutate_initial_state_congestion_05_const`,
`agent_mutate=mutate_mixture_geometric_proposal_lambda_0` — i.e. the same
env/policy materialization as `mixture_probability_toy_study`, differing only
in name (which determines the results directory).

### 3. `param_generation/cli.py` — new recipe, activated in `main()`

`recipe_toy_eval_proposal_comparison()`:

1. asserts the trained coefficients load successfully from
   `experiments/results/mixture_probability_toy_study` before generating
   anything (no silent retraining),
2. loops over the three arms, calling `generate_test_paths_and_init_state`
   with `test_sample_path_num=4096`, `warm_up_periods=0`,
   `is_require_penalty_coefficients=True`,
   `policy_ids=['approx_penalized_hindsight']`, the arm's
   `evaluation_proposal_spec`, and
   `penalty_coefficients_dir='experiments/results/mixture_probability_toy_study'`,
   collecting the returned records (`dat_file=None` per call),
3. writes ALL 3 x 4096 = 12288 records into a single `table.dat` split into
   500 groups via `write_grouped_command_file`.

`main()` is switched to call this recipe, so `python generate_params.py`
produces the full 12288-record `table.dat` in one invocation.

## Data flow (unchanged downstream)

Each dat record is self-contained: `sample_path`, `period_weights`,
`policy_specs` (with embedded trained coefficients), `experiment_name`.
`run.py::calculate_policy_costs_with_penalty` consumes groups as today and
applies the IS `period_weights` to the post-warm-up costs/penalties. Results
land in `experiments/results/<experiment_name>/pickles`, so aggregation
separates the arms by directory with no changes.

## Error handling

* Coefficient loading returning `None` aborts the recipe with a clear error
  (assert before generation) instead of falling back to retraining.
* `build_proposal` already rejects malformed specs.
* The fixed-length computation asserts `int(geom.ppf(0.99, 0.01)) == 459`.

## Verification

Unit tests (pytest, toy env, small path counts, e.g. 8 per arm):

1. geometric-0.99 arm: `period_weights` all equal 1;
2. fixed arm: every sampled path has 458 arrivals and `period_weights` has
   459 entries equal to `0.99**(t-1)`, t = 1..459;
3. mixture arm: weights within `[1, 10]`;
4. regression guard: calling `generate_test_paths_and_init_state` WITHOUT the
   new parameters produces records identical to the pre-change behavior;
5. embedded `policy_specs` are byte-identical across the three arms.

Smoke test: run the recipe at reduced scale and check dat records carry all
required fields (`sample_path`, `period_weights`, `policy_specs`,
`generating_function_spec`).
